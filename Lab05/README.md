N = 21, K = 17, a = 0, b = 1, c = 1

## Параметри варіанта
* **Завдання 1 (a = 0):** Дужки `( ) [ ] { }`, повертає результат та індекс першої помилки.
* **Завдання 2 (b = 1):** Зворотний польський запис (RPN) з операціями `+`, `-`, `*`, `/` та `%` (остача).
* **Завдання 3 (c = 1):** Черга обслуговування з 10 заявок (`8 + K % 5`), що надходять у різні моменти часу. Обчислення часу простою.
* **Завдання 4:** Власний стек поверх масиву з початковою місткістю 3 (`K % 4 + 2`) та подвоєнням на 4-му `Push`.

## Результати обов'язкових тестів

### Завдання 1 (Баланс дужок)
* `"(a[b]{c})"` -> Збалансований: **True**, Індекс помилки: **-1**
* `"([)]"` -> Збалансований: **False**, Індекс помилки: **2**
* `")("` -> Збалансований: **False**, Індекс помилки: **0** (закривальна дужка при порожньому стеку)
* `"(("` -> Збалансований: **False**, Індекс помилки: **2** (непорожній стек після кінця рядка)
* `""` -> Збалансований: **True**, Індекс помилки: **-1**

**Тест з $K=17$ відкривальними та $K-1=16$ закривальними дужками:**
* Вхідний рядок: `"((((((((((((((((())))))))))))))))"` (33 символи)
* Результат: **False**, Індекс помилки: **33** (після зчитування всього рядка стек містить 1 непарну відкривальну дужку).

### Завдання 2 (Зворотний польський запис)
* `"3 4 + 2 *"` -> Результат: **14**
* `"5 3 -"` -> Результат: **2**
* `"8 2 /"` -> Результат: **4**
* `"2 3 4 * +"` -> Результат: **14**
* `"5 0 /"` -> Помилка: **Ділення або остача від ділення на нуль!**

**Власний вираз із результатом $K = 17$:**
* Вираз: `"5 4 * 10 7 % -"`
* Обчислення: $5 \times 4 = 20$, $10 \pmod 7 = 3$, $20 - 3 = 17$.
* Результат: **17**

## Завдання 5. Обґрунтування та аналіз

### 1. Обґрунтування вибору структур для завдань 1–3:

* **Завдання 1 (Перевірка дужок - Стек):** Задача вимагає парності за принципом LIFO (Last-In, First-Out): остання відкрита дужка має закриватися першою. Застосування черги замість стеку зламало б алгоритм, оскільки закривальна дужка порівнювалася б з найпершою відкритою дужкою виразу, що призвело б к фальшивим помилкам для всіх вкладених дужок вида `([()])`.
* **Завдання 2 (Польський запис - Стек):** Обчислення виразу в RPN вимагає збереження операндів до моменту появи оператора, який застосовується до двох останніх збережених чисел (LIFO). Якби замість стеку використали чергу, операнди біля оператора бралися б з початку виразу, порушуючи математичну пріоритетність та порядок виконання дій.
* **Завдання 3 (Обслуговування заявок - Черга):** Задача моделює реальне обслуговування за принципом FIFO (First-In, First-Out) — заявки обслуговуються суворо в порядку їх надходження. Використання стеку призвело б до того, що нові заявки обслуговувалися б першими, а найперші заявки безкінечно застоювалися б у глибині стеку.

### 2. Чому `Queue.Dequeue()` дешевший за `List.RemoveAt(0)`:
Метод `List.RemoveAt(0)` має часову складність **$O(N)$**, оскільки після вилучення першого елемента він змушений фізично зсувати всі $N-1$ елементів масиву на одну позицію ліворуч (що було доведено замірами з Лабораторної роботи 4: `Insert(0)` та `RemoveAt(0)` потребують зсуву елементів і виконуються понад **1400 мс** для 100 000 елементів). 

Натомість `Queue<T>` реалізована як **кільцевий буфер (Circular Buffer)** з двома вказівниками (`head` та `tail`). Операція `Dequeue()` просто збільшує вказівник `head` на 1 та повертає елемент за постійний час **$O(1)$** (близько **0.01 мс**), повністю уникаючи копіювання чи зсуву елементів у пам'яті.

## Висновок

Під час виконання лабораторної роботи №5 було опановано використання базісних структур даних — **Стеку (LIFO)** та **Черги (FIFO)** у мові C#. Згідно з варіантом ($N = 21, K = 17$) успішно реалізовано:
1. Алгоритм перевірки збалансованості дужок із точним визначенням індексу першої помилки та обробкою крайових випадків.
2. Обчислювач зворотного польського запису (RPN) з підтримкою операцій `+`, `-`, `*`, `/`, `%` та захистом від ділення на нуль.
3. Модель черги обслуговування з розрахунком часу простою та максимальної довжини черги.
4. Власний стек `CustomCharStack` на основі масиву з автоматичним подвоєнням місткості.
