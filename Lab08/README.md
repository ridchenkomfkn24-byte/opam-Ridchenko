N = 21, K = 17, a = 0, b = 1, c = 1

## Параметри варіанта
* **Масив ($a = 0$):** `int[]` — 100 000 цілих чисел з діапазону [0; 340], генератор `new Random(21)`.
* **Порівняння `cmp`:** Стандартне порівняння чисел (`CompareTo`). $X = 170$, $Y = 204$.
* **Відсутнє значення:** `341`.
* **Основний запит ($b = 1$):** Індекс останнього входження $X = 170$.
* **Варіант пошуку ($c = 1$):** Бінарний пошук без перевірки на рівність у циклі.

## Завдання 1. Пояснення лінійного пошуку

При лінійному пошуку елемента, якого **немає в масиві (341)**, алгоритм змушений здійснити обхід від першого до останнього елемента і виконати рівно $N = 100\,000$ порівнянь. Натомість для елементів, які присутні у масиві, обхід переривається одразу при першому збігу (наприклад, для першого елемента — всього 1 порівняння).

---

## Завдання 2. Прояв чотирьох поломок бінарного пошуку

1. **`while (lo < hi)` замість `lo <= hi`:**  
   Якщо елемент знаходиться на останній позиції, де `lo == hi` (наприклад, останній елемент масиву або випадок з 1 елементом), цикл завершується до перевірки останнього кандидата і функція повертає `-1` (елемент «не знайдено»).
2. **`lo = mid` замість `lo = mid + 1`:**  
   Коли `hi = lo + 1`, обчислення `mid = lo + (hi - lo) / 2` дає `mid = lo`. У випадку, якщо `a[mid] < target`, виконується присвоєння `lo = mid`, тобто `lo` не змінюється. Алгоритм потрапляє у **безкінечний цикл (зависає)**, оскільки межі перестають звужуватися.
3. **`mid = (lo + hi) / 2`:**  
   На навчальному масиві у 100 000 елементів ця версія працює абсолютно правильно, тому що максимальна сума індексів не перевищує $199\,999$. Переповнення типу `int` (`int.MaxValue = 2 147 483 647`) виникне лише тоді, коли розмір масиву перевищить приблизно **1.07 мільярда елементів** ($lo + hi > 2^{31}-1$).
4. **Невідсортований масив:**  
   При тестуванні 100 запитів наявних у невідсортованому масиві значень алгоритм повернув `-1` у **74 з 100 випадків**, оскільки принцип відкидання половини масиву працює лише на впорядкованих даних.

## Завдання 3. Пошук межі та некоректна умова

За допомогою єдиного методу `FindFirst` отримано:
* Індекс першого входження $X = 170$: `49911` (порівнянь: 17).
* Верхня межа $X = 170$: `50212` (порівнянь: 17).
* **Індекс останнього входження $X = 170$ ($b = 1$):** `50211`.
* **Кількість елементів, рівних $X$:** $50212 - 49911 = 301$ елемент.

**Чому кількість порівнянь не залежить від кількості рівних елементів:**  
Алгоритм бінарного пошуку межі не зупиняється при першому знаходженні елемента $X$, а завжди ділить інтервал навпіл суворо $\lceil \log_2 N \rceil$ разів.

**Спроба знайти перший елемент, кратний 7 некоректною умовою `x % 7 == 0`:**  
Алгоритм повернув хибний індекс `0` (значення `0`), а для числа `1` повернув би неправильну відповідь. Умова `val % 7 == 0` не є монотонною відносно впорядкованого масиву (значення прапорця змінюється з хаотичними стрибками `true/false`), тому бінарний пошук для неї незастосовний.

## Завдання 4. Варіант пошуку $c = 1$

В алгоритмі бінарного пошуку без перевірки на рівність у циклі звуження меж відбувається за умовою `cmp(a[mid], target) < 0`.

| Запит | Класичний бінарний (порівнянь) | Варіант c = 1 (порівнянь) |
| :--- | :---: | :---: |
| **Елемент X = 170** | 2 | 18 |
| **Перший елемент масиву** | 32 | 18 |
| **Відсутній елемент 341** | 34 | 18 |

**Чому порівнянь на крок стало менше, а кроків — на один більше:**  
У кожній ітерації циклу виконується **лише одне порівняння** замість двох (відсутній блок `if (res == 0)`). Оскільки цикл не переривається достроково при збігу, він завжди робить повні $\lceil \log_2 N \rceil$ кроків, а остаточна перевірка рівності здійснюється один раз після завершення циклу.

## Завдання 6. Висновок та відповіді на питання

1. **Зміряне число точки окупності ($q \approx 45\text{--}50$) проти теоретичних 34:**  
   Теоретична оцінка враховує виключно кількість математичних порівнянь. У реальності алгоритм `Array.Sort` несе додаткові накладні витрати на виклики методів, локальність кешу процесора та переміщення елементів у пам'яті. Через це реальний секундомір показує окупність сортування при трохи більшій кількості запитів ($q \approx 45\text{--}50$).

2. **Два питання до даних, на які відповідає бінарний пошук, але не відповідає хеш-структура:**  
   * Пошук діапазону значень або найближчого сусіда (наприклад, першого елемента, не меншого за $X$, або елементів у межах $[X; Y]$).
   * Отримання порядку елементів (найменший / найбільший елемент, $k$-та порядкова статистика) без повного перебору даних.

3. **Вибір структури при динамічному потоці даних з оновленням після кожного запиту:**  
   Якщо масив постійно змінюється після кожного запиту, постійне повне сортування $O(N \log N)$ буде надто дорогим. Для забезпечення швидкого пошуку і швидких вставок/вилучень слід обрати **збалансоване дерево пошуку** або комбінацію **Хеш-структури** (для пошуку за $O(1)$) з двозв'язним списком/деревом.
