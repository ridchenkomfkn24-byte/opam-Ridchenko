## Завдання 5. Захоплення змінних (Closure Pitfalls)

### Фактичний вивід коду:
```text
1. Змінна після лямбди: check(100) = False
2. Цикл for: 3 3 3 
3. Цикл foreach: 0 1 2 
```

### Пояснення ситуацій:

1. **Змінна після лямбди:**  
   Лямбда-вираз захоплює не поточне *значення* змінної `threshold`, а посилання на саму змінну (контекст/замикання). Коли значення `threshold` було змінено з `17` на `1000`, делегат під час виклику прочитав вже оновлене значення `1000`. Тому `100 > 1000` повернуло `False`.

2. **Лічильник циклу for:**  
   Усі три лямбда-вирази захопили **одну й ту саму** змінну лічильника `i`. До моменту, коли делегати були викликані після завершення циклу, значення `i` вже досягло кінцевої умови `3`. У результаті всі три делегати зчитали поточне значення цієї єдиної змінної `i` (тобто `3`).

3. **Цикл foreach:**  
   Починаючи з C# 5.0, у циклі `foreach` ітераційна змінна `item` створюється заново на кожній ітерації циклу (своя область видимості). Тому кожна лямбда захопила власну окрему змінну із відповідним значенням (`0`, `1`, `2`).

### Як виправити ситуацію 2 у циклі for:
Щоб лямбди у циклі `for` повертали різні значення, слід створити локальну копію змінної всередині тіла циклу:
```csharp
for (int i = 0; i < 3; i++)
{
    int copy = i; // Локальна копія змінної для кожної ітерації
    actionsFor.Add(() => copy);
}
```
