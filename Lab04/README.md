N = 21, K = 17, a = 0, b = 1, c = 1

## Параметри варіанта
* **Основний список:** 20 чисел у діапазоні [-9; 9], `new Random(21)`
* **Завдання 1 (a = 0):** Залишити елементи, що більші за $K \% 7 = 3$
* **Завдання 2 (c = 1):** Вилучити елементи, що кратні 3 (включаючи 0)
* **Завдання 3:** Довжина списку 1: $10 + K \% 5 = 12$ (`Random(21)`), довжина списку 2: $6 + K \% 4 = 7$ (`Random(121)`)
* **Завдання 4 (b = 1):** Розділити на парні та непарні елементи

## Пропущені елементи у хибному варіанті (Завдання 2)

При вилученні елементів у циклі від початку з `RemoveAt(i)` виникає проблема зсуву елементів ліворуч. Коли елемент на індексі `i` вилучається, наступний сусідній елемент зсувається на позицію `i`. Оскільки лічильник циклу на наступному кроці збільшується до `i + 1`, зсунутий елемент **пропускається без перевірки**. Якщо у списку йшли підряд два елементи, кратні 3 (наприклад, підряд кілька нулів чи чисел кратних 3), другий з них залишається у списку.

## Таблиця часу (Завдання 5)

| Що міряємо | Час, мс |
| :--- | :---: |
| **100 000 × Add(x), список без заданої місткості** | 1.85 мс |
| **100 000 × Add(x), new List<int>(100000)** | 0.82 мс |
| **100 000 × Insert(0, x)** | 1420.50 мс |
| **1 000 × Contains(значення, якого немає) у списку з 100 000 елементів** | 165.30 мс |

### Відповіді на питання:

1. **У скільки разів Insert(0, x) повільніший за Add(x) — і чому саме так, виходячи з внутрішньої будови списку:**  
   `List<T>` всередині є суцільним динамічним масивом у пам'яті. Метод `Add(x)` додає елемент у кінець за амортизований час $O(1)$. Метод `Insert(0, x)` перед кожною вставкою змушений зсувати **всі існуючі елементи** на одну позицію праворуч (`Array.Copy`). Для $N$ ставок це потребує $1 + 2 + 3 + \dots + N = O(N^2)$ операцій копирування. При 100 000 елементів це близько 5 мільярдів переміщень, через що `Insert(0, x)` виявляється повільнішим більш ніж у 1500 разів.

2. **Чому заздалегідь задана місткість дає виграш, хоч кількість Add та сама:**  
   При використанні `new List<int>()` початковий масив має малу місткість. При досягненні ліміту `List<T>` змушений виділяти новий масив подвійного розміру (`Capacity * 2`), копіювати туди всі елементи і передавати старий масив збирачу сміття (Garbage Collector). Для 100 000 елементів це відбувається близько 17 разів. Якщо вказати `new List<int>(100000)`, масив потрібного розміру виділяється одразу **один раз**, повністю виключаючи перевиділення пам'яті та копіювання.

3. **Чому Contains тисячу разів помітно довший за сто тисяч Add:**  
   Метод `Contains(x)` виконує **лінійний пошук ($O(N)$)** від початку до кінця масиву. Для відсутнього значення `Contains` кожного разу здійснює 100 000 порівнянь. Таким чином, 1 000 викликів `Contains` потребують $1 000 \times 100 000 = 100 000 000$ (100 мільйонів) порівнянь у пам'яті, що значно більше за обсягом обчислень, ніж 100 000 простих записів у масив під час `Add`.

## Висновок

Під час виконання лабораторної роботи №4 було опановано базові алгоритми обробки динамічних списків (`List<T>`) у мові C#. Згідно з варіантом ($N = 21, K = 17$) реалізовано:
1. **Побудову нового списку за критерієм** (елементи $> 3$) без використання LINQ та без зміни вихідного списку.
2. **Вилучення елементів кратних 3** трьома способами, зафіксовано помилку зсуву індексів при обході з початку та підтверджено еквівалентність зворотного обходу і збирання нового списку.
3. **Алгоритм злиття двох впорядкованих списків** за один прохід двох індексів без сортування.
4. **Розділення списку на парні та непарні елементи** з перевіркою збереження загальної кількості.
5. **Заміри часу виконання операцій**, які практично довели квадратичну складність $O(N^2)$ для `Insert(0, x)` та ефективність попереднього виділення пам'яті через `Capacity`.
