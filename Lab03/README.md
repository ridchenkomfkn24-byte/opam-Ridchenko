## Вивід трасування (Завдання 4)

```text
enter Max(0..3)
  enter Max(0..1)
    enter Max(0..0) -> 8
    enter Max(1..1) -> 20
  exit  Max(0..1) -> 20
  enter Max(2..3)
    enter Max(2..2) -> -2
    enter Max(3..3) -> -19
  exit  Max(2..3) -> -2
exit  Max(0..3) -> 20
```

### Пояснення порядку виходів
Рядки `exit` з'являються у зворотному порядку до `enter` через принцип роботи системного стеку викликів LIFO (Last In, First Out). Кожен батьківський виклик чекає завершення обчислень у своїх дочірніх функціях, тому виклики найглибшого рівня завершуються та виходять зі стеку першими.

## Відповіді на питання (Завдання 5)

1. **Який запис зрозуміліший для цієї задачі — рекурсивний чи циклічний, і чому:**  
   Для задачі пошуку максимуму в одновимірному масиві циклічний запис є значно зрозумілішим та ефективнішим. Він має просту лінійну структуру O(N), зчитується послідовно, не вимагає обчислення проміжних індексів поділу масиву та не створює додаткових накладних витрат на виклики функцій у пам'яті.

2. **Чому так само просто переписати циклом завдання 1 не вийде і якої структури даних бракує:**  
   Завдання 1 (обхід каталогів) неможливо легко переписати звичайним циклом, оскільки для збереження шляхів до ще не відвіданих підпапок потрібна явна допоміжна структура даних — **Стек (Stack)** або **Черга (Queue)**. Під час рекурсії роль такої структури автоматично виконує системний стек викликів (Call Stack), запам'ятовуючи точку повернення. У звичайному циклі без використання явного стеку чи черги програма втратить зв'язок із батьківськими папками після занурення вглиб.

## Перевірка крайових випадків

* **Порожня папка (Завдання 1):** Очікується глибина 0. Отримано: 0.
